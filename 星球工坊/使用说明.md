# 使用说明 · 星球工坊（PlanetForge，词条写入 · cfg 驱动）

> **机制已实机验证**：tag `9`（掠食变种）写到星球 `215` 后，进游戏该星球的任务界面左侧
> 「**敌情预测 // 情报与侦察**」出现 `[超级掠食者] 强化追猎虫变种`。
> **注意**：**星系地图上不显示**这类词条图标——验收一律看**游戏内的任务面板 / 敌情预测 / 局内**。
>
> 这一版**不需要**在 Arsenal 里选星球/词条组合：所有配置写在**外部文本**里，改完约 **2 秒生效**，不用退出游戏（更不用重导 mod）。

---

## 1. 装一次（配置由包自己创建，不需要你复制任何文件）

1. Arsenal 里**删掉旧的 PlanetForge 条目**（写入测试包 / 快照包都删），导入 `dist\PlanetForge.zip` 并**启用**；
2. **Purge → Deploy**；
3. 启动游戏 —— 日志首行出现 `this line means the addon loaded` 即已加载（进对局前就能确认）；
4. **包会在首次加载时自己创建配置**：优先 `%APPDATA%\Arrowhead\Helldivers2\planetforge.cfg`，
   目录不可写时依次退到 `%APPDATA%\planetforge.cfg`、`%LOCALAPPDATA%\planetforge.cfg`；
   创建时写一行 `CFG created template at <路径>`；
5. **换批次会自动迁移**：若盘上那份是**包自己生成的、你还没编辑过**的旧模板，新包会**先把它备份成
   `<cfg>.bak` 再刷新成当前批次**，并记 `CFG refreshed: template v… -> v4; the previous content is in …`；
   **你编辑过的文件永不覆盖**，只会记一行 `CFG kept: this file has been edited`；
   （连"上一版包连状态文件都没留"的老文件也能识别：只要首行是 `# PlanetForge` 就算我们生成的。）
6. 想改就直接编辑那个文件（**约 2 秒生效**，不用退游戏、不用重导）；改完后日志会写
   `PLANETFORGE ready: cfg=<路径> lines=<行数> ignored=<问题数> writes_total=<累计写入次数>`。

> **配置没找到时不会静默**：包会自己建一份模板并在日志里写明路径。
> **换批次时也不会静默**：它会刷新（或明确说"你改过，我不动"）。

## 2. 配置怎么写

```
# 以 # 开头是注释
planet 215 tag 9                 # 一颗星球一个词条
planet 253 tag 12,24             # 一颗星球多个词条：**超过 5 个会自动溢出到第二行**
planet 224 tag 27 filter 4       # filter 必须显式写（见下表）
unlock 126 faction 2             # 解锁：让现在进不去的星球变成"可攻打"（见 §2.1）
```

| 字段 | 含义 |
|---|---|
| `planet` | 战争地图星球 **id**（1–400）。名字表下一版注入；**id 才是权威** |
| `tag` | **tag 表索引 0–31**（逗号分隔可多个；**每行最多 5 个，超出自动占用下一行**）。完整字典见 §2.2 |
| `filter` | 该词条作用到哪个阵营的任务：**1 超级地球 / 2 终结族 / 3 机器人 / 4 光能者**。**请显式写出**——不写会去读该星球当下阵营，实机里那次读取取不到值会**静默回退成 2**，导致光能者/机器人星球上的词条"什么都不显示"（**已修**：每行都会记 `FACTION planet=… live=… used=… source=cfg\|auto`，一眼看出是否回退） |

### 2.1 `unlock`（第二项能力：把进不去的星球变成可攻打）——**2026-10-02 实机验证成功**

```
unlock <星球id> [faction 1-4] [plan 125|127] [rows on|off] [policy same|any|terminid|...]
                [state <n>] [source <星球>] [exclude <星球>[,<星球>]]
```
**已验证的效果**：把 **126 图灵**（原本"超级地球控制、不可进入"）变成**终结族控制 + 可进入 + 真的有任务**
（局内看到 `开拓地任务/取回侦察机情报`，敌情预测里出现我们挂的词条）。

**能成功的三条关键**（缺一不可，都是照参考实现的做法）：
1. **整份复制任务行**：一颗星球的 110 行任务表里，属于它的那些行就是**一整套作战**；**抄一部分会被游戏丢弃**
   （之前我留了 12 行上限 ⇒ 一直失败，去掉后立刻出任务）。日志：`UNLOCK task rows planet=126 copied=30 of 30 …`；
2. **只在"目标星球是当前视图"时写**（悬停/选中它即可，约 2 秒内触发，日志 `UNLOCK triggered by view`）——
   任务表同一时刻只装"你所看那颗星球"的行；
3. **来源星球必须与目标阵营一致**（`policy same`，默认）：抄来的行**就是那颗星球的阵营专属作战**。
   所以给**机器人**目标就先把 `faction` 写成 3、并**先去看一颗可攻打的机器人星球**（如 262）；
   **光能者**同理（`faction 4`，先看 224）。

**它做两件事**（都带**快照 + 回读 + 异常回滚**）：
1. **改星球动态记录**：`plan 125`（默认）只写 `available→1` + `faction`；
   `plan 127`（隐藏星球那套、**尚未验证**）额外写 `timer→0`、`state@28→5`；
2. **复制任务行**（`plan 125` 默认开启，`rows on|off` 可强制）：来源＝**同阵营、id 最小、不在排除名单**的星球；
   槽位＝**先复用目标自己已有的有效行、再用未生效的行**；补丁只改星球字段，写完逐行读回。
   日志：`UNLOCK scan: …` → `UNLOCK source planet=… (faction 2 (same as target), lowest id), N validated row(s)` →
   `UNLOCK task rows planet=… copied=N of M row(s) from planet=…`。

**一次加载里同时开多颗**：直接写多条 `unlock` 行即可（各自阵营独立）。但**每颗都要"你亲眼看它一次"**才会被写入
（任务表只装当前视图星球的行）——所以流程是：先看一颗**可攻打**的同阵营星球喂模板（如 215/262/224），
再依次**选中每颗要解锁的星球**；下次要在这颗星球上开打前，**再选它一次**让它重新写一遍即可。

**⚠️ 注意**：特殊星球（268、KEPLER-361b 99 这类）不要用；**把某条 `unlock` 行删掉即自动还原**该星球的记录与任务行
（日志 `UNLOCK released planet=…`）。

**⚠️ 两层是独立的（很容易混）**：
- **`unlock`** → 决定这颗星球**有哪些任务**（写的是任务行）；
- **`planet <id> tag …`** → 决定它的**敌情预测里出现哪些变种**（写的是全局修饰表，**按星球 id 生效**）。

所以**每解锁一颗新星球，都要单独给它写一条 tag 行**，否则它只会显示游戏自带的普通词条。
（实例：127 天使投资解锁后任务正常，但起初没有特殊变种 —— 补上 `planet 127 tag 9,10,11 filter 2` 后就有了。）

## 4. 配置生成器（不用手写 cfg）

三种用法，任选：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **图形生成器** | 双击 `星球工坊/配置生成器.html`（单文件、零依赖）→ 选模板星球/阵营/词条 → 加目标星球并标注**无人星球**或**隐藏星球** → 生成 cfg 或**下载配方 JSON** | 想看着表点选 |
| **一键安装** | 双击 `星球工坊/生成配置.bat`：它会**自动用 Downloads 里刚下载的 `planetforge.cfg`**（没有就装默认配方）；也可以把 `planetforge.cfg` / 配方 `.json` **拖到这个 bat 上** | 已有文件，想直接生效 |
| **命令行** | `python 星球工坊\tools\cfg_gen.py --spec 配方.json --install`（`--import 现有.cfg` 读回配置、`--report` 只校验、`--list-planets` 看可选星球、`--list-tags` 看词条字典） | 脚本化/批量 |

> 生成器（HTML）里改完配置后，**最省事的替换路径**：①点 `下载 planetforge.cfg` ②双击 `生成配置.bat` —— 它会自己找到刚下载的那份并替换（**先备份**原文件）。

**它做了什么**：按插件相同的顺序**自动找到真正的 cfg**（`%APPDATA%\Arrowhead\Helldivers2\planetforge.cfg` → `%APPDATA%` → `%LOCALAPPDATA%`），**先把原文件备份**成 `planetforge.cfg.bak-<时间戳>`，再写入新配置 ⇒ 游戏内约 2 秒热重载生效，想还原就用备份覆盖回去。

**规则**（生成器会强制）：①「模板星球 → 多个目标星球」的 C/S 结构；②**每颗星球最多 5 个词条**；③目标星球必须标注是**无人星球**（在图上、进不去 ⇒ `plan 125`）还是**隐藏星球**（不在图上 ⇒ `plan 127 rows on`，会写 timer/state 把它调出来）；④268 / 99 等禁止槽位直接拒绝。

**默认配方＝包内初始配置**：不改任何东西直接生成，得到的就是插件自带的那套（215/262/224 作为来源 → 235/152/238/126/127），所以"没替换 cfg"时行为和现在完全一致。

## 4. 判读日志（`%LOCALAPPDATA%\PlanetForge.log`）

| 你看到 | 含义 |
|---|---|
| `planet forge installed -- this line means the addon loaded` | **自证行**：包已加载 |
| `modifier table at 0x…; 32 rows x 356 bytes` | 表地址与区域属性检查通过 |
| `CFG loaded: 8 line(s) accepted, 0 ignored` | 配置读入（`loaded` 首次 / `reload` 热重载） |
| `CFG created template at <路径> -- edit it in place; changes apply within ~2 s` | **首次加载时包自己创建了配置**（内含批 2 的 13 行） |
| `PLANETFORGE ready: cfg=<路径> lines=13 ignored=0 writes_total=13` | 每次配置**变化后**的总结行（配置没变时**不会重复刷屏**） |
| `WRITE ok #1 row=0 planet=215 tags=9,10 filter=2 count=2` | **某行写入成功**（回读也校验过），row 就是表里的行号 |
| `WRITE skipped planet=…: no free row` | 32 行全被真事件占了（罕见）⇒ 会少写几条 |
| `WRITE released row=… (planet … is gone from the config)` | 配置里删掉了该星球，**该行已还原** |
| `CFG ignored: …` | 某一行有问题被跳过（其余照常） |
| `WRITE aborted: …` | 指针/区域检查没过 ⇒ **一个字节都没写**（把日志发我） |

## 5. 安全边界

- **只动 count=0 的空行**，真事件行一律不碰；每行**快照 + 回读 + 异常回滚**；
- 只在**已提交 / 私有 / 可读写**且 ≥ 32×356 字节的区域里写；不写可执行页、不调原生函数、不改任务行；
- **一次会话有效**，重启游戏即还原；改配置随时可撤（删掉那行 → 该行还原）。
